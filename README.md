# ORBITAL 分子工作室 · v1.2.0

以三維模型為中心的分子編輯器，提供 Windows 本機版與連接雲端計算的私人網頁版。常用操作集中在模型與情境工具中，保留逐顆接原子、立體構型、量測、檔案與構象搜尋功能。

## v1.2.0 化學式與電子結構

主要化學式採常用書寫順序，例如銨離子顯示 **NH₄⁺**；元素個數用下標、同位素質量數及總電荷用上標。原本的 Hill 化學式保留在「資訊 → 結構式與索引」，供資料索引使用。`NH4+` 與 `H4N+` 表示相同組成，畫面優先使用較符合閱讀習慣的形式；此規則不是通用化學命名引擎。

對含共軛系統的結構，模型旁可切換 **離域示意** 與 **Lewis 式**：

- **離域示意**：顯示局域電子對，將參與共軛的電子計入整個 π 系統。經共振式與結構對稱性判定的等價鍵使用一致的實線／虛線表示。
- **Lewis 式**：依目前 Lewis 電子配置顯示完整孤電子對與形式電荷，每一組兩點表示一對電子。電子點附著於原子附近，取代舊版懸浮的小框紫色標記。
- **π 軌域示意**：在「顯示」面板獨立開關；一個 p 軌域有兩葉瓣，不能把兩瓣計為兩對電子。

例如 O₃ 的 Lewis 式有 6 對孤電子對；離域示意呈現 5 對局域電子對與含 4 個電子的 π 系統，兩個 O–O 鍵外觀一致。這是同一分子的兩種表示方式，切換不會更改連接圖、三維座標或匯出結構，也不表示分子在共振式之間來回切換。

羧基 OH 氧的 Lewis 孤電子對仍為 **2 對**，其中一對可參與共軛。羧酸的 C=O 與 C–OH 不等價，並不因共軛而強制畫成相同鍵；羧酸根等經驗證的等價鍵則一致表示。OH 的 p 軌域依本身局部幾何定向，扭轉後不強制與羰基保持平行，C–O–H 角也不因 SP2 標籤而硬改為 120°。

電子點、葉瓣、示意鍵級及 π 電子計數用於理解結構，**不是量子電子密度或實算分子軌域**，不提供定量的共振貢獻權重。羧酸、醯胺等的共振資料採有限的 Lewis 配置列舉；不得把列出的配置數量當作完整物理描述。

## Windows 本機版啟動

使用包含 `runtime/`、`python_lib/` 與 `dist/` 的完整 Windows 版本資料夾，雙擊 `launch.cmd`。程式會啟動本機引擎並開啟瀏覽器；不用另外安裝 Python 或 Node.js。若已開啟舊版，先用該版的 `stop.cmd` 停止，再開啟新版。使用完畢可用新版 `stop.cmd` 停止服務。

通常網址為 `http://127.0.0.1:8765`；連接埠占用時會尋找 8765–8785。計算與檔案處理在本機執行。整個版本資料夾需一同保留。

## iPad 與私人網頁版

私人網頁入口：[ORBITAL 分子工作室](https://orbital-molecular-studio.a1593711534.chatgpt.site)。Sites 已發布；2026-11-01 已確認 Render 計算服務部署為 `live`，公開 `/healthz` 回傳 HTTP 200、版本 `1.2.0`。Sites 登入後的完整計算流程及真實 iPad 尚待驗證，詳見 `VALIDATION.md`。

部署架構為：`iPad Safari → Sites 私人網頁 → 伺服器代理 → Render Python／RDKit`。完成部署後，使用交付的 Sites 網址並登入具存取權的 ChatGPT 帳號；家中 Windows 電腦不必保持開機。Render 的網址是計算 API，並非模型操作介面。部署與實機驗證狀態見 `VALIDATION.md`。

原始碼保存在 [GitHub](https://github.com/a1593711534-droid/orbital-molecular-studio)；Render 連接 `main` 分支，使用 `deploy/Dockerfile` 建置，已設定 On Commit。這次透過連線工具上傳提交後未觀察到自動部署，因此已手動觸發並確認成功；後續更新仍應確認部署狀態。私人網頁由 Sites 另行部署。只更新 GitHub 不會自動發布新的 Sites 前端版本；前端與後端須各自完成對應發布流程。GitHub Pages 單獨無法執行此版的 Python／RDKit 計算。

雲端版需要網路。Render 免費服務閒置後可能需要等待啟動，介面會保留原結構並提示等待或重試。新增原子、改鍵、最佳化及輸入預覽使用相同化學引擎；驗證密鑰僅保存在伺服器環境變數中，不由使用者填寫，也不放入瀏覽器程式。

**專案自動儲存在目前裝置、目前瀏覽器的本機儲存空間，不是跨裝置雲端同步。** 私人網站登入不會自動把 Windows 暫存移至 iPad。要換裝置或長期保存，請匯出專案 JSON，再於另一台裝置匯入；清除瀏覽資料或使用無痕模式可能失去暫存。Windows 的 `127.0.0.1` 暫存與 Sites 網址的暫存也彼此獨立。

觸控操作為單指拖曳旋轉、雙指縮放與平移、輕點選取；拖曳與多指操作不應觸發接原子。桌面模擬觸控與畫面尺寸測試不代表已完成 iPad Safari 實機驗證。

## 不必先背 SMILES

「輸入結構」保留可直接貼上或編輯的 SMILES，並加入可點選的常用元素、單雙三鍵、支鏈、回主鏈與環連接工具。輸入時自動顯示 2D 連接圖；點下方的符號籤可了解該符號並定位輸入位置。未閉合的括號、環或尚未接完的鍵會給出短提示。輸入不會改動畫布，只有按「生成三維結構」成功後才會套用。

畫布提供全部 12 種支援元素；矽等需要括號及氫數的進階 SMILES 可原樣貼上，或直接在畫布接原子。2D 預覽只驗證連接與基本模型適用性，三維取樣仍可能因幾何限制而失敗。

## 逐顆建立順式／反式

選碳，以單鍵接成四碳鏈 → 點中間的化學鍵改成雙鍵 → 選順式（Z）或反式（E）。兩端各有一個氫的 C=C 同時顯示順／反名稱；其他可編輯結構使用依 CIP 優先序判定的 E／Z。圖示的實心點代表用來比較的取代基。

設定構型會重新生成三維形狀，保留 π 鍵旋轉鎖定。清除指定後仍會顯示一個取樣構象，但不把它當作已指定的異構物。相同取代基、累積雙鍵及環內雙鍵等不適用情況會顯示原因；若複雜共軛系統無法保留其他既有構型，操作會取消。

## 檔案與立體資訊

JSON 專案保存原始立體指定範圍；MOL／SDF 匯入需有三維座標，並可能依座標推導立體化學。XYZ 只保存元素與座標。JSON 不包含完整候選構象池，載入後可再次搜尋。

新增、刪除或替換相關原子與鍵時會重設受影響的立體標記；修改後請重新確認 E／Z。四面體立體中心可由含 `@`／`@@` 的 SMILES 指定。

## 化學模型與適用範圍

幾何生成使用 **ETKDGv3** 距離幾何與構象取樣，後續優先以 **MMFF94s** 力場最佳化，適用時回退至 **UFF**。介面會揭露實際使用的方法、能量與警告。能量只能在相同分子、相同方法與一致設定之間作相對比較；不同力場或不同分子的數值不宜直接比較。

生成座標是計算模型得到的構象或局部能量極小值，**不是實驗量測，也不保證是唯一或全域最低能量結構**。溶劑、溫度、晶體堆積、反應過程及量子電子效應不在此版本的求解範圍內。對柔性分子，應比較多個構象；對實驗級或研究結論，仍需適當的量子化學或實驗方法驗證。

經驗證的處理範圍為中心電子域不超過四個的常見主族閉殼層分子，包含 H、B、C、N、O、F、Si、P、S、Cl、Br、I；最多 80 個重原子及 200 個含氫原子。PF₅、SF₄、SF₆ 等需要五／六電子域的超價中心會明確拒絕，避免通用力場產生錯誤的三角雙錐、蹺蹺板或八面體。無法參數化的結構、金屬配位與自由基等會拒絕處理或明確標示限制，避免顯示未受模型支持的精確外觀。

含硼結構使用 UFF 時，介面會明確提示鍵長與能量的定量誤差；即使 BF₃ 平面形狀正確，也不將 UFF 數值當成高精度實驗結果。

### CO₂ 的參考幾何

CO₂ 的通用 MMFF／UFF 鍵長在驗證中顯示偏差，因此本版對辨識出的中性 CO₂ 使用 [NIST CCCBDB 的氣相實驗參考座標](https://cccbdb.nist.gov/exp2x.asp?casno=124389&charge=0)：C–O 1.1621 Å、O–C–O 180°。介面明確標示「NIST 參考幾何」，能量留空，不冒充力場最佳化結果；三維匯入則保留輸入座標。

### O₃ 的參考幾何

生成或最佳化辨識出的中性臭氧時，使用 [NIST CCCBDB 氣相實驗參考幾何](https://cccbdb.nist.gov/expgeom2x.asp?casno=10028156&charge=0)：兩個 O–O 鍵皆為 **1.278 Å**，O–O–O 為 **116.8°**，力場能量留空。匯入的 O₃ 仍保留原座標；之後明確執行最佳化，才套用參考幾何。

### 鍵旋轉

- 雙鍵、三鍵與芳香鍵不提供自由旋轉；旋轉多重鍵會破壞 π 鍵模型。
- 醯胺 C–N 鍵因共振限制而鎖定。
- 環內鍵不允許以單鍵切割方式旋轉；環構象需由整體幾何生成處理。
- 其他共軛單鍵可能可旋轉，但存在扭轉能障；介面會標示此區別。可旋轉不代表無能量代價。

### 孤電子對與 π 顯示

孤電子對以電子計數及局部幾何建立方向示意，並區分局域電子對與參與共軛的電子對。半透明葉瓣與電子點是理解幾何的示意符號，**不是量子化學計算的電子密度、機率分布或等值面**。π 軌域顯示也屬示意；葉瓣大小與透明度不具有定量物理意義。

## 檔案與開發

- `dist/`：可直接由本機服務提供的前端成品。
- `src/`：React 與 Three.js 原始碼。
- `chemistry.py`：RDKit 化學與幾何計算。
- `server.py`：僅供本機使用的 HTTP 服務。
- `deploy/`：Render 用 ASGI 計算 API、隔離計算子程序、Dockerfile 與固定版本套件清單；部署方式見 `deploy/README.md`。
- `runtime/`、`python_lib/`：隨附執行環境與化學套件。
- `tests/`：化學與服務驗證程式。

GitHub 原始碼不包含大型 Windows 執行環境與套件資料夾；可攜版本需使用完整交付資料夾。修改前端後，需在已安裝 Node.js 的環境執行 `npm ci` 與 `npm run build`。直接啟動服務可執行 `runtime\python.exe server.py --port 8765`。 從 GitHub 原始碼自行安裝時，可使用 Python 3.12 執行 `python -m pip install -r requirements.txt`，完成前端建置後執行 `python server.py --port 8765`；原始碼下載不含可攜式執行環境。此版本的前端為 React 19、Three.js 0.180，化學引擎為 RDKit 2025.09.6。
